# Plate Gate — распознавание номеров и открытие шлагбаума

Камера Imou → вебхук → снимок → распознавание номера (CPU, ONNX) → белый список →
SIP-звонок на шлагбаум + уведомление в Telegram. Всё в `docker compose`.

```
Imou cloud ──push──▶ https://ДОМЕН/webhook/imou/<секрет>
                          │
                          ▼
             снимок (картинка события / setDeviceSnapEnhanced / RTSP)
                          │
             YOLOv9-tiny (поиск номера) + fast-plate-ocr (чтение)
                          │
           номер в белом списке? ──да──▶ SIP INVITE на шлагбаум
                          │
                          └──────────▶ Telegram (номер + снимок)
```

## Нагрузка

| | |
|---|---|
| Распознавание кадра | ~40–50 мс на 1 ядре (YOLOv9-t-384 + cct-xs) |
| ОЗУ контейнера | ~100 МБ в простое, ~300 МБ под нагрузкой |
| Образ | ~700 МБ, модели встроены (работает без доступа к GitHub) |

Подойдёт самый младший Contabo VPS. На ваших 5 фото: 5 из 5 номеров распознаны верно
(`docker compose exec app python -m tests.test_anpr`).

## Установка

1. Установите Docker на VPS: `curl -fsSL https://get.docker.com | sh`
2. Откройте порты: `ufw allow 80,443/tcp` (если включён ufw).
3. Скопируйте папку на сервер и запустите настройку:
   ```bash
   scp -r plate-gate root@IP_СЕРВЕРА:~/
   ssh root@IP_СЕРВЕРА
   cd plate-gate && ./setup.sh
   ```
   Скрипт спросит APP_ID, APP_SECRET и дата-центр Imou. Потом он создаст `.env` с паролем админки,
   запустит контейнеры и покажет адрес админки.
4. Откройте `https://1-2-3-4.sslip.io/`, где `1-2-3-4` — это IP вашего сервера через дефисы.
   Логин `admin`, пароль покажет `setup.sh`.

### Без своего домена

Домен покупать не нужно. Imou принимает вебхук только по HTTPS, а сертификат на голый IP получить нельзя.
Поэтому используется бесплатный сервис **sslip.io**: адрес `5-189-10-20.sslip.io` всегда указывает на IP `5.189.10.20`.
Caddy сам получает на этот адрес настоящий сертификат Let's Encrypt.
IP сервера определяется автоматически, его можно также указать в `PUBLIC_IP`.
Если позже появится свой домен, впишите его в `DOMAIN` и выполните `docker compose up -d`.

### Что указать в `.env`

- `IMOU_APP_ID`, `IMOU_APP_SECRET` — из консоли open.imoulife.com.
- `IMOU_API_HOST` — адрес вашего дата-центра. Его видно в консоли Imou: **Basic Information → My Information**.
  Обычно это `https://openapi-sg.easy4ip.com` (Сингапур) или `https://openapi-fk.easy4ip.com` (Франкфурт).
  Проверить можно кнопкой «Проверить подключение» в админке.
- `DOMAIN`, `PUBLIC_IP` — можно оставить пустыми (см. «Без своего домена»).
- `WEBHOOK_SECRET` — длинная случайная строка (`openssl rand -hex 16`). Это защита вебхука от посторонних.
- `ADMIN_PASSWORD` — пароль для админки.

## Настройка в админке (по порядку)

1. **Imou / вебхук** → «Проверить подключение» → «Включить вебхук».
   По умолчанию подписываемся на `alarm,faceAnalysis,capabilityEvent`.
2. **Камеры** → «Импортировать камеры из аккаунта Imou» (или добавьте вручную по серийному номеру).
   Кнопка «снимок + распознать» проверит цепочку, не открывая шлагбаум.
3. **Белый список** — номера по одному в строке, можно с владельцем: `901 CX 01 Иванов`.
4. **Настройки → Telegram** — токен бота от @BotFather и chat id, затем «Отправить тестовое сообщение».
5. **Настройки → SIP** — данные SIP-аккаунта и номер шлагбаума, затем «Тестовый звонок».
6. В приложении Imou включите у камеры **обнаружение автомобилей** (AI-детекция, «умное обнаружение» и т.п.).
   Если камера этого не умеет, подойдут детекция движения или пересечение линии в зоне въезда.
7. Проедьте мимо камеры и откройте **Imou / вебхук → Последние входящие сообщения**. Там видно, какой `msgType` прислала камера
   (например `aiVehDetect`, `detection.vehicle.detected`, `crossRegionDetection`, `human`).
   Если этого типа нет в **Настройки → Типы событий**, добавьте его.
   Если очистить поле, распознавание будет запускаться на любое событие с камеры.

## Как это работает

- **Снимок.** Сначала берётся картинка из самого события, если Imou её приложила. Потом RTSP, если он указан у камеры
  и VPS до неё достаёт. Иначе используется `setDeviceSnapEnhanced` через облако Imou.
  Делается до 4 снимков с интервалом 1 с. Цикл останавливается, как только найден уверенный номер.
- **Распознавание.** Детектор `yolo-v9-t-384-license-plate-end2end` (open-image-models), OCR `cct-xs-v2-global-model`
  (fast-plate-ocr). Оба работают на ONNX Runtime, только CPU. Результат проверяется на формат номеров РК
  (`901CX01`, `724AJW02`, старый `A123BCD`).
- **Белый список.** Сверка строгая. В настройках можно разрешить 1 ошибочный символ, но это снижает безопасность.
  Кириллица при вводе понимается (`901 СХ 01` = `901CX01`).
- **Защита от повторов.** Один и тот же номер повторно открывает шлагбаум не раньше, чем через 30 с (настраивается).
  Повторные push с тем же `id` игнорируются.
- **SIP.** Встроенный лёгкий SIP-клиент работает по UDP с Digest-авторизацией. Он звонит на номер шлагбаума,
  ждёт ответа и кладёт трубку. Может послать DTMF через SIP INFO.
  Ответы `486 Busy` / `603 Decline` считаются успехом: так обычно ведёт себя GSM-реле, когда сбрасывает разрешённый вызов.
  Аудио (RTP) не передаётся.
- **Хранение.** SQLite и снимки лежат в `./data`. Снимки старше `KEEP_DAYS` удаляются.

## Полезные команды

```bash
docker compose logs -f app                          # логи
docker compose exec app python -m tests.test_anpr   # проверка распознавания на примерах
docker compose pull caddy && docker compose up -d --build   # обновление
```

Если админка нужна без домена, сделайте SSH-туннель: `ssh -L 8000:127.0.0.1:8000 root@VPS` → http://localhost:8000.

## Ограничения и что проверить на месте

- Формат push-сообщений Imou зависит от модели камеры. Обработчик понимает все три формата из документации
  (`did/cid/msgType`, `iotEvent`, `capabilityEvent`). Но точный `msgType` вашей камеры лучше посмотреть
  во «входящих сообщениях» (шаг 7).
- Облачный снимок приходит с задержкой 1–3 с. Если машина проезжает быстро, поставьте камеру так,
  чтобы машина стояла перед шлагбаумом, или дайте VPS доступ к RTSP камеры (VPN/проброс порта).
- SIP работает только по UDP. Если провайдер требует TCP/TLS, нужна доработка.
